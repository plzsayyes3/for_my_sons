# わんこ大図鑑「自作 / 所持」分岐 設計仕様

## 目的

既存の図鑑トップレベル分類（「なかま」「てき」「元素」）を維持したまま、「なかま」だけを「自作」と「所持」に分ける。ローカル自作わんこの管理操作を追加し、正式キャラクター・ゲーム進行・登録依頼のデータ境界を保つ。

## 現状と制約

- `wanko-library/index.html` が図鑑画面と描画・タブ選択を担当している。
- `shared/wanko-library.js` は `for-my-sons-wanko-library` IndexedDB の `wankos` ストアを管理している。
- ローカル自作わんこは `WankoLibrary.listWankos()` で `archived !== true` のものだけ取得される。
- `shared/wanko-library-view.js` は正式・ゲーム内キャラクター、敵、元素のカードモデルを生成する。
- `shared/wanko-game-progress.js` の現在の図鑑連携は既存の進行状態を読み取り、正式・ゲーム内キャラクターの解放判定を行う。今回の変更では進行データを書き換えない。
- 登録依頼は共有IndexedDBの `characterRequests` ストアにあり、自作わんこのアーカイブとは別のライフサイクルである。
- 正式キャラクター関連ファイルと公開カタログは変更しない。
- 作業開始時点の未コミット変更（`wanko-library/index.html` と `wanko-war/index.html` の既存キャッシュ番号変更）は保持し、今回の変更で上書きしない。

## 採用方針

既存の図鑑ページを中心に拡張する。データ分類は既存の共有モジュールを利用し、削除可能なデータ操作だけを `shared/wanko-library.js` に追加する。正式・ゲーム内カードの既存生成経路は再利用する。

### 表示モデル

トップレベルのタブは次のままにする。

```text
なかま / てき / 元素
```

`なかま`選択時だけ、内部タブを表示する。

```text
自作 / 所持
```

「自作」は `WankoLibrary.listWankos()` の結果だけを表示する。各カードは画像、名前、作成日、使用中表示、登録依頼状態、削除ボタン、必要時の登録依頼導線を持つ。

「所持」は、既存の正式キャラクター一覧と、既存のゲーム進行から解放済みと判定できるキャラクターを表示する。正式・ゲーム内カードは削除操作を持たない。敵と元素は現在の描画経路を維持する。

### 自作カードの状態

- 使用中判定は既存の `WankoLibrary.getActiveWanko()` と公式選択状態を組み合わせる。
- 登録依頼済み判定は、依頼JSONや画像を図鑑DBへコピーせず、共有IndexedDBの `characterRequests` を読み取り専用で照合する。
- 照合は自作わんこに保存された依頼識別子がある場合に限る。識別子がまだない旧データは未依頼として扱い、勝手に依頼を作成しない。
- 登録依頼済みの自作わんこをアーカイブしても、`characterRequests` レコード、画像Blob、リモートの `character-requests/pending/<requestId>/` は変更しない。

### アーカイブと使用中切り替え

`WankoLibrary.archiveWanko(id)` を追加する。物理削除は行わず、対象レコードを `archived: true`、`updatedAt` を現在時刻へ更新して保存する。

削除対象が使用中の場合は、次の順で安全に処理する。

1. 未アーカイブの別の自作わんこがあれば、それを `setActiveWanko` で使用中にする。
2. それがなければ active ID をクリアする。

アーカイブ後、`listWankos()` と `getActiveWanko()` を再取得して図鑑を再描画する。自作DBのクラウド同期が設定済みなら、既存の `syncNow()` 経路を使って `archived` 状態を同期する。登録依頼同期とは別の処理である。

確認UIは次の内容を含める。

```text
このわんこを削除する？
削除すると、この端末の図鑑から見えなくなります。
```

キャンセル時はIndexedDB、active状態、依頼データを変更しない。

### 登録依頼ボタン

既存依頼がない自作わんこにだけ、必要に応じて登録依頼導線を表示する。依頼作成処理はPaintの共有サービスを再利用し、図鑑側へGitHub Contents APIを実装しない。依頼の作成に必要な陣営情報が旧レコードにない場合は、陣営選択を要求するか、今回の範囲では導線を表示しない。

## 変更対象

- `shared/wanko-library.js`
  - `archiveWanko` と必要最小限の読み取り・active切り替え補助を追加。
- `shared/wanko-library-view.js`
  - 自作カードと所持カードの分類を純粋関数として追加し、既存の敵・元素カード生成を変更しない。
- `wanko-library/index.html`
  - 内部タブ、カード状態、削除確認UI、アーカイブ後の再描画を追加。
  - 既存の「てき」「元素」のDOM・描画経路を維持する。
- `tests/wanko-library.test.js` または既存の関連テスト
  - IndexedDBアダプタを含むアーカイブとactive切り替えのテスト。
- `tests/wanko-library-view.test.js`
  - 自作 / 所持分類、削除不可属性、既存の敵・元素回帰テスト。
- `tests/static-shell.test.js`、`tests/service-worker.test.js`、`service-worker.js`
  - 図鑑HTMLまたは依存スクリプトのバージョン変更が必要な場合だけ更新する。

正式キャラクター一覧、`official-wankos/`、`assets/official-wankos/`、Wanko Warの進行保存形式、`character-requests` の同期パスは変更しない。

## エラー処理

- IndexedDBの読み書き失敗時はカード操作を完了扱いにせず、画面にエラーを表示する。
- 削除確認のキャンセルは成功・失敗の通知を出さず、表示だけを維持する。
- 依頼照合に失敗しても、自作わんこの表示や削除を壊さない。依頼状態は「確認できない」または未依頼として扱い、依頼データを削除しない。
- 公式・ゲーム内カードに削除イベントを登録しない。

## テスト方針

次をテストファーストで追加する。

- 内部タブ「自作 / 所持」が存在する。
- 自作モデルはローカルわんこのみを含む。
- 所持モデルは正式・解放済みゲーム内キャラクターを含む。
- 自作をアーカイブすると一覧から除外され、レコード自体は復元可能な状態で残る。
- キャンセルではレコードと一覧が変わらない。
- 正式・ゲーム内カードに削除可能フラグがない。
- 使用中の自作をアーカイブしても、別の自作への切り替えまたはactive解除が行われる。
- 依頼済み自作のアーカイブが `characterRequests` や登録依頼パスを変更しない。
- プロフィール別Wanko War進行と118元素の状態が変わらない。
- 既存の敵、元素、正式キャラクター、PWAシェルのテストが通る。
